# Discord-бот панели

Верификация игроков и автоматическая прописка на сервер. Бот **ничего не хранит
и ничего не решает сам** — вся истина в панели, поэтому расходиться нечему.

## Как это работает

1. Игрок пишет `/verify` — бот отвечает **только ему** одноразовой ссылкой.
   Ссылка личная: кто её открыл, тот и привяжет свой Steam к этому Discord.
2. Игрок входит через **Steam** на странице панели. Пароль он вводит на сайте
   Steam; ни бот, ни панель его не видят. Владение аккаунтом подтверждает сам
   Steam (OpenID), поэтому подделать steamId64 нельзя.
3. Панель пишет связку и **ставит прописку в очередь на диске**. Дальше она
   допишет игрока в файлы сервера сама: с повторами, без дублей, даже если файл
   занят сервером или панель перезапустили. Именно поэтому «человек пришёл, а
   его не прописало» больше не случается — прописка не зависит от бота.
4. Бот выдаёт роль и ставит ник из Steam. Если бот в этот момент лежал, он
   догонит пропущенных при старте (`/api/verify/pending`, раз в 30 с).

## Настройка

Токен бота и ID (сервер Discord, роль «проверен», канал журнала) задаются **в
панели**, в мастере настройки: на машине с панелью откройте
`http://127.0.0.1:8787/setup.html` → раздел «Discord».

Боту локально нужны только две строки. Скопируйте `.env.example` в `.env`:

```
PANEL_URL=http://127.0.0.1:8787
PANEL_TOKEN=dzp_…
```

`PANEL_TOKEN` — API-токен **с правами admin**: панель → Настройки → «Аккаунты и
права» → API-токены.

## Запуск

Windows — `start-bot.bat` в корне репозитория. Вручную:

```bash
pip install -r requirements.txt
python bot.py
```

Панель должна быть запущена: настройки бот берёт у неё.

## Из чего состоит

Модули в `modules/`, каждый добавляет свои команды:

| Модуль | Что делает |
|---|---|
| `verification.py` | верификация, роли, догонялка после падения бота |
| `serverinfo.py` | состояние сервера, живое сообщение в канале статуса, статус бота |
| `admin.py` | управление сервером и игроками из Discord |
| `groups.py` | фракции из `GroupSpawner.json` |
| `tickets.py` | обращения приватными ветками; кнопки, вопросы и тексты приходят из панели |

`panel.py` — единственное место, где бот знает про HTTP.

## Команды

| Команда | Кто | Что делает |
|---|---|---|
| `/verify` | все | выдаёт личную ссылку на подтверждение Steam |
| `/status [участник]` | все | подтверждён ли Steam и прописан ли игрок в каждом файле |
| `/server` | все | состояние сервера: онлайн, карта, аптайм, ближайший перезапуск |
| `/online` | все | кто сейчас на сервере (без координат) |
| `/groups` | все | фракции и сколько в них людей |
| `/group-members фракция` | все | состав фракции |
| `/close [итог]` | автор, поддержка | закрыть обращение внутри его ветки |
| `/tickets` | поддержка | открытые обращения и обращения в работе |
| `/whitelist участник steam_id` | админы | связать и прописать вручную |
| `/unverify участник` | админы | снять связку и роль |
| `/group-add участник фракция` | админы | вписать во фракцию (нужен подтверждённый Steam) |
| `/say текст` | админы | написать игрокам в игру |
| `/restart-server [warn]` | админы | перезапустить сервер, по умолчанию с предупреждением в игру |
| `/player ник` | админы | карточка игрока: здоровье, голод, координаты, что в руках |
| `/kick ник [причина]` | админы | выгнать с сервера |
| `/adminlog` | админы | последние действия админов, включая VPPAdminTools |
| `/tickets-panel` | админы | поставить в канале кнопки обращений (по кнопке на форму) |

«Админы» — администраторы Discord или носители роли, указанной в мастере
настройки («ID роли админов»). Панель проверяет права ещё раз, по API-токену:
токен `read` ничего изменить не сможет, кем бы ни была вызвана команда.

### Обращения настраиваются в панели

Вкладка сервера **«Обращения»**: формы (каждая — своя кнопка со своим цветом,
эмодзи и надписью), вопросы к каждой форме (до пяти — столько показывает Discord
в одном окне), роли поддержки и наблюдателей отдельно для каждой формы, тексты
при открытии, при «взять тикет» и при закрытии, надписи самих кнопок «взять» и
«закрыть», лимит открытых обращений на человека и удалять ли ветку при закрытии.

Бот ничего из этого не знает наизусть: он читает настройку и рисует то, что в
ней. Добавили форму — вызовите в Discord `/tickets-panel` в нужном канале.

Переписка каждого обращения складывается в панель, поэтому её можно прочитать и
после того, как Discord заархивирует ветку — на той же вкладке, в карточке
обращения, вместе с ответами на вопросы.

Каналы и роли (статус, журнал, тикеты, поддержка, админы) задаются в мастере
настройки панели. Бот перечитывает их раз в 5 минут — перезапускать его из-за
смены ID не нужно. Смена **токена бота** требует перезапуска.

## Чего в боте пока нет

Торговец из прежнего бота (≈3400 строк: товары, цены, категории, история сделок)
не перенесён. Это отдельная задача сравнимого объёма, и делать её вслепую, без
исходного файла, значит переписать наугад. Остальное из прежнего набора —
верификация, тикеты, фракции, админ-команды, состояние сервера — здесь есть.

## Права бота в Discord

- включите **Server Members Intent** в настройках приложения (Bot → Privileged
  Gateway Intents) — без него нельзя выдать роль по id;
- роль бота должна быть **выше** выдаваемой роли, иначе Discord ответит
  «нет прав». Бот пишет об этом прямо.

## Если что-то не так

Бот печатает причину словами, а не трейсбек:

| Сообщение | Что делать |
|---|---|
| `панель недоступна по адресу …` | запустите панель, проверьте `PANEL_URL` |
| `Нужен API-токен с правами admin` | токен `read` не годится: в ответе настоящий токен бота |
| `В панели не задан токен бота` | мастер настройки → Discord → «Токен бота» |
| `Discord не принял токен бота` | Bot → Reset Token, вставьте новый в мастер настройки |
| `нет прав выдать роль` | поднимите роль бота выше выдаваемой |
