# Промпт для интеграции сайта и Discord-бота с панелью DayZ

> Этот файл — готовое задание для другой модели (GPT), которая пишет сайт и
> Discord-бота. Отдайте ей ссылку на репозиторий `Paneldayzserver` и текст ниже.
> Всё, что нужно знать о панели, есть здесь: адреса, авторизация, форматы
> ответов, живой поток событий и границы возможного.

---

## 0. Роль и задача

Ты пишешь **сайт** и **Discord-бота** для сервера DayZ Standalone. Данные и
управление ты берёшь не с игрового сервера напрямую, а у уже готовой **панели
управления** (репозиторий `Paneldayzserver`). Панель — Node.js/Express
приложение на Windows-машине, где стоит сам сервер DayZ. Она уже умеет:

- запускать/останавливать/перезапускать сервер, плановые перезапуски;
- ставить и обновлять моды через SteamCMD;
- писать игрокам в игру (BattlEye RCon либо CFTools Cloud);
- через собственный серверный мод `@DayZPanelBridge` видеть игроков онлайн, их
  координаты, здоровье, инвентарь, и вести подробный журнал действий;
- выдавать всё это по HTTP JSON API и живым потоком SSE.

**Твоя работа — только клиент.** Не проектируй свой опрос игрового сервера, не
разбирай логи DayZ, не подключайся к BattlEye — всё это уже сделано в панели.
Если для сайта или бота не хватает какого-то маршрута, **не придумывай его**:
напиши, какого именно эндпоинта не хватает и какие поля в нём нужны, — маршрут
добавят в панель.

## 1. Как устроена связь

```
   Игровой сервер DayZ  ──► мод @DayZPanelBridge ──► файлы обмена
                                                          │
                                                          ▼
   твой сайт / Discord-бот  ◄── HTTP + SSE ──►  Панель (Express, порт 8787)
```

- Базовый адрес: `http://<адрес-панели>:<порт>/api` (по умолчанию порт `8787`).
- Всё общение — JSON, кодировка UTF-8, тексты ошибок на русском.
- Ошибка всегда приходит как `{"error": "текст"}` c кодом 4xx/5xx. Показывай
  этот текст как есть — он написан для человека.
- Панель однопользовательская и не рассчитана на большую нагрузку. Не опрашивай
  её в цикле чаще, чем раз в 5 секунд; для живых данных используй SSE (§4).

## 2. Авторизация: только API-токены

У панели два способа входа, и для тебя годится **ровно один**.

| Способ | Кому | Годится тебе? |
|---|---|---|
| Мастер-ключи (3 ключа вида `RBEA-RFUS-RCAY`) | человеку в браузере | **Нет.** Они генерируются заново при каждом запуске панели и живут только в памяти. |
| API-токен `dzp_…` | сайту, боту, скриптам | **Да.** Живёт в `config/config.json`, переживает перезапуск панели, отзывается по одному. |

### Как получить токен

Владелец панели открывает её в браузере → **Настройки** → «Доступ к панели» →
«API-токены для интеграций» → создаёт токен, выбирает область прав и копирует
значение. **Значение показывается один раз** — дальше видно только начало
строки. Токены нельзя создать самим токеном: маршруты `/api/auth/*` (ключи,
сессии, токены) доступны только живой сессии по мастер-ключу и вернут 403 с
`{"auth":"session"}`.

### Области прав

| Область | Что можно |
|---|---|
| `read` | только `GET` и `HEAD`. Любой `POST/PUT/PATCH/DELETE` → 403. |
| `admin` | всё, что умеет панель: запуск сервера, команды игрокам, моды. |

**Правило для тебя: сайту выдай `read`, боту — `read`, и только если у бота
есть админ-команды, отдельный токен `admin`.** Никогда не используй один токен
на публичную часть сайта и на админку.

### Как передавать токен

```bash
# основной способ
curl -H "Authorization: Bearer dzp_xxxxxxxx" http://panel:8787/api/status

# альтернативный заголовок
curl -H "X-Panel-Token: dzp_xxxxxxxx" http://panel:8787/api/status

# только для EventSource, у которого нельзя задать заголовки
http://panel:8787/api/stream?token=dzp_xxxxxxxx
```

Токен в query-строке попадает в логи прокси — используй `?token=` только для
SSE и только по HTTPS либо внутри доверенной сети.

### Ответы авторизации, которые надо обрабатывать

| Код | Тело | Что значит | Что делать |
|---|---|---|---|
| 401 | `{"error":"…","auth":"required"}` | токена нет вовсе | не повторять, чинить конфигурацию |
| 403 | `{"error":"API-токен не найден или отозван","auth":"token"}` | токен отозвали | остановить опрос, сообщить админу |
| 403 | `{"error":"Токену «…» разрешено только чтение (POST запрещён)","auth":"token"}` | нужен `admin` | не повторять |
| 403 | `{"error":"…","auth":"session"}` | это маршрут только для браузера | не трогать |

Не делай авто-повтор при 401/403 — токен сам не починится, а панель считает
неудачные попытки.

### Безопасность, о которой нельзя забыть

- Токен — это доступ к серверу DayZ. Храни в переменных окружения
  (`PANEL_URL`, `PANEL_TOKEN`), не в коде и не в git.
- **Никогда не проксируй запросы к панели с публичной страницы, подставляя
  токен на клиенте.** Токен живёт только на бэкенде сайта/бота; браузер и
  Discord-пользователь общаются с твоим бэкендом, а он — с панелью.
- Панель по умолчанию работает по HTTP. Если она открыта в интернет, попроси
  владельца включить TLS (`panel.tls` в конфиге) или поставить перед ней
  reverse-proxy с сертификатом.
- Не публикуй наружу без фильтра: точные координаты игроков, содержимое
  инвентарей, IP-хэши, чат. Это данные для админов, а не для сайта.

## 3. Многосерверность

Панель ведёт несколько серверов DayZ. Почти каждый маршрут работает с одним из
них:

- `?serverId=<id>` — конкретный сервер;
- без параметра — **активный** сервер панели.

Список серверов: `GET /api/servers` → `{ servers: [{ id, name, installed, … }] }`.
В сайте и боте всегда передавай `serverId` явно: активный сервер админ может
переключить в любой момент, и молчаливая смена контекста — источник самых
неприятных багов.

## 4. Живой поток: SSE `/api/stream`

Один поток на всё. Открывай **одно** соединение на процесс, а не по одному на
пользователя сайта, и раздавай события своим клиентам уже сам (WebSocket,
опрос — как удобно).

```js
const es = new EventSource(`${PANEL_URL}/api/stream?token=${PANEL_TOKEN}`);
es.addEventListener('bridge-players', (e) => onPlayers(JSON.parse(e.data)));
es.addEventListener('bridge-events', (e) => onEvents(JSON.parse(e.data)));
```

При подключении панель сразу присылает текущее состояние (`backlog`,
`statuses`, `restarts`, `announcements`, `bridge-status`, `bridge-players`),
поэтому отдельный «первый запрос» не нужен.

| Событие | Данные | Зачем тебе |
|---|---|---|
| `backlog` | массив строк лога | начальная история лога |
| `log` | `{ ts, level, source, message }` | лог панели, по одной записи |
| `statuses` / `status` | состояние серверов / одного сервера | «сервер онлайн/офлайн» на сайте |
| `servers` | краткий список серверов | список изменился |
| `job` | `{ id, type, progress, state, … }` | ход установки/загрузки модов |
| `restarts` / `restart-plan` | план перезапусков | «до перезапуска N минут» |
| `restart-warning` | `{ minutes, text, … }` | продублировать предупреждение в Discord |
| `announcements` / `announcement` | состояние и текст объявлений | зеркалить объявления в чат Discord |
| `bridge-status` | `{ serverId, online, playersOnline, world, … }` | жив ли мод-мост |
| `bridge-players` | `{ serverId, players: [...], worldSize }` | онлайн-карта, счётчик игроков |
| `bridge-events` | `{ serverId, events: [...] }` | живая лента действий игроков |

Переподключение: `EventSource` в браузере переподключается сам; в Node.js
(`eventsource`-пакет или свой `http`-клиент) реализуй переподключение с
задержкой 5–30 с. После обрыва добери пропущенное через `GET /api/events?since=<ts>`.

## 5. Маршруты, которые тебе действительно нужны

### 5.1 Состояние сервера (для сайта: «сервер онлайн, 23/60 игроков»)

```
GET /api/status
```
Возвращает: `hasServers`, `activeServerId`, `servers[]`, `statuses`,
`server` (состояние активного), `problems[]` (человеческие предупреждения),
`restart` / `restarts` (план перезапусков), `announcements`, `steamcmd`,
`jobs[]`, `panel` (версия, платформа, Node).

Этого достаточно для блока «статус сервера» на сайте и команды `/status` в боте.

### 5.2 Игроки онлайн и карта

```
GET /api/bridge                  # жив ли мод-мост и почему нет
GET /api/bridge/players          # игроки с координатами и состоянием
GET /api/bridge/trails?minutes=15
GET /api/bridge/players/:id/trail?minutes=30
GET /api/bridge/players/:id/inventory     # запрос уходит в игру, ждёт ответ мода
```

`GET /api/bridge` → `{ installed, online, reason, protocol, modVersion, world,
worldSize, playersOnline, snapshotAt, gameTime, … }`. **Всегда проверяй
`online`**: если мод-мост не на связи, `players` будет пустым, а `reason`
содержит готовое объяснение для админа («мод-мост не установлен…», «мод молчит:
сервер остановлен…»). Показывай `reason`, а не «0 игроков».

Игрок в `/api/bridge/players`:

```json
{
  "id": "76561198000000000",
  "steam64": "76561198000000000",
  "name": "Survivor",
  "pos": [7500.2, 320.1, 8100.7],
  "dir": 1.57,
  "health": 100, "blood": 5000, "shock": 0,
  "hunger": 2100, "thirst": 2400, "energy": 1800, "water": 2000,
  "temperature": 36.5, "heatComfort": 0.1, "wet": 0,
  "stamina": 90,
  "bleeding": false, "unconscious": false, "restrained": false,
  "hands": "SKS", "vehicle": null,
  "playtimeSec": 4310, "ping": -1
}
```

Тонкости, на которых легко ошибиться:

- `pos` — это `[x, y, z]` в метрах, где **`y` — высота**, а карта плоская в
  координатах `x` (восток) и `z` (север). Для карты берёшь `pos[0]` и `pos[2]`.
- Размер мира — в `worldSize` (метры, обычно 15360 для Черноруси). Не
  захардкоживай.
- `ping` равен `-1`, если пинг недоступен — не показывай «-1 мс».
- `heatComfort` — не температура тела, а комфорт по теплу: `-1` замерзает, `+1`
  перегрев.
- `id` = Steam64 игрока. По нему связывай аккаунты сайта/Discord с игроками.

Трасса: `{ playerId, name, online, minutes, worldSize, points: [{ ts, x, z }],
distanceM }`.

Инвентарь — единственный «медленный» GET: панель кладёт задание моду и ждёт
ответа до 10 секунд. Не вызывай его в цикле и не дергай по таймеру для всех
игроков; ставь таймаут 15 с на своей стороне.

### 5.3 Журнал действий игроков

```
GET /api/events?types=chat,kill&playerId=765…&search=…&since=<ms>&before=<ms>&limit=200&days=3
GET /api/events/summary?hours=24
GET /api/events/files
```

Ответ: `{ events: [...], limit, online }`. Событие:

```json
{
  "id": 1234,
  "ts": 1770000000000,
  "type": "kill",
  "playerId": "765…", "playerName": "Killer",
  "targetId": "765…",  "targetName": "Victim",
  "pos": [7500, 320, 8100],
  "data": { "weapon": "SKS", "distance": 143.2 }
}
```

Типы событий (`type`): `connect`, `spawn`, `disconnect`, `death`, `kill`,
`damage`, `shot`, `chat`, `item_take`, `item_drop`, `item_move`, `action`,
`vehicle_enter`, `vehicle_exit`, `vehicle_engine`, `vehicle_destroy`, `build`,
`dismantle`, `container_open`, `placement`, `unconscious`, `bleeding`, `admin`,
`command_result`, `server`.

`data` у каждого типа своё и **не гарантировано**: мод — внешний код, поля
могут отсутствовать. Читай через безопасный доступ и не падай на `undefined`.
Готовые русские подписи и однострочные описания событий уже написаны в
`public/js/screens/map.js` (`EVENT_LABELS`, `eventLabel`, `eventText`) —
переиспользуй эту логику, чтобы формулировки на сайте и в панели совпадали.

`GET /api/events/summary?hours=24` даёт готовую сводку по типам — идеально для
ежедневного отчёта в Discord.

История хранится 30 дней в файлах по дням; `days` — насколько глубоко смотреть
(по умолчанию 3). Не тяни весь месяц одним запросом.

### 5.4 Сообщения в игру

```
GET  /api/ingame                # каким каналом и готов ли он
POST /api/ingame/say            { "text": "..." }
```

`GET /api/ingame` → `{ channel, delivery: { ok, channel, reason, maxLength },
battleye: {...}, cftools: {...} }`.

**Перед отправкой всегда смотри `delivery.ok` и `delivery.maxLength`**: длина
сообщения ограничена каналом (BattlEye — около 200 символов, CFTools — 256).
Если `ok:false`, в `reason` лежит причина по-русски — покажи её админу вместо
«не отправилось». Отправка сообщений требует токена `admin`.

Отдельно: `GET /api/announcements`, `POST /api/announcements/send`,
`POST /api/announcements/preview` — периодические объявления в игровой чат.
В шаблонах работают подстановки `{server}`, `{map}`, `{restart}`, `{minutes}`.

### 5.5 Управление (только токен `admin`, только для админ-команд бота)

```
POST /api/server/start | /api/server/stop | /api/server/restart
POST /api/bridge/command    { "action": "...", "args": { ... } }
GET  /api/mods            POST /api/mods/update    POST /api/mods/deploy
GET  /api/missions        POST /api/missions/select
GET  /api/battleye/players POST /api/battleye/command
```

Команды мода (`POST /api/bridge/command`) — то, чем панель воздействует на
игру. Ответ: `{ ok: true, action, result }`; если мод не на связи или отказал,
приходит ошибка с текстом причины.

| `action` | `args` |
|---|---|
| `ping` | — (проверка связи с модом) |
| `message` | `id` (Steam64), `text`, `style`: `popup` \| `important` |
| `kick` | `id`, `reason` |
| `teleport` | `id`, `pos: [x, y, z]` |
| `teleport_to` | `id`, `targetId` |
| `heal` | `id` |
| `set_stat` / `add_stat` | `id`, `stat`: `health`\|`blood`\|`shock`\|`hunger`\|`thirst`\|`energy`\|`water`\|`temperature`\|`stamina`, `value` / `delta` |
| `give_item` | `id`, `itemClass`, `quantity`, `where`: `hands`\|`inventory`\|`ground` |
| `remove_item` | `id`, `itemClass` (или `all`) |
| `inventory` | `id` (лучше через `GET …/inventory`) |
| `godmode` | `id`, `on` |
| `kill` | `id` |
| `spawn_object` | `itemClass`, `pos: [x, y, z]`, `quantity` |
| `set_time` | `hour`, `minute` |
| `set_weather` | `overcast`, `rain`, `fog`, `windForce` (0…1) |

`save_world` существует, но осознанно возвращает ошибку: сохранить мир из
скрипта надёжно нельзя, для этого есть плановый перезапуск.

Важно: поле класса предмета называется **`itemClass`**, а не `class` (`class` —
зарезервированное слово в Enforce Script). Полный протокол моста и все
расхождения с «идеальным» описанием — в `docs/bridge-mod-prompt.md`.

**Любое действие бота, меняющее состояние игры, обязано быть под правами
Discord-ролей и записано в свой аудит-лог.** Панель не знает, кто из твоих
пользователей нажал кнопку — различай это на своей стороне.

### 5.6 Чего у панели нет

Не рассчитывай на: список банов без CFTools (маршруты `/api/cftools/*`
работают только при включённой платной интеграции CFTools Cloud), веб-хуки от
панели наружу (панель никуда сама не звонит — инициатива всегда твоя),
привязку Discord-аккаунтов к Steam64 (это твоя задача), донат-платежи,
статистику killboard за всё время (есть журнал за 30 дней — агрегируй сам и
храни у себя).

## 6. Как построить интеграцию (рекомендуемая архитектура)

1. **Один сервис-адаптер** («panel-client») в твоём проекте: базовый URL,
   токен, таймауты, разбор `{error}`, единый SSE-коннект с переподключением.
   И сайт, и бот пользуются им, а не `fetch` в разных местах.
2. **Своя база** для того, что панель не хранит: привязка Discord ↔ Steam64,
   агрегированная статистика, история дольше 30 дней. Наполняй её из
   `bridge-events`/`/api/events` — это твой источник истины по событиям.
3. **Кэш на 5–15 секунд** для публичных страниц сайта: онлайн, статус,
   счётчики. Панель не выдержит трафик сайта напрямую.
4. **Разделение прав**: публичная часть сайта — только `read` и только
   безопасные поля; админка сайта и админ-команды бота — отдельный `admin`
   токен на бэкенде.
5. **Деградация**: панель может быть недоступна (машина админа, перезапуск).
   Сайт должен показывать последние известные данные с отметкой времени, а не
   ошибку 500; бот — отвечать «панель недоступна», а не молчать.

### Минимальный клиент (Node.js)

```js
const BASE = process.env.PANEL_URL;      // http://panel:8787
const TOKEN = process.env.PANEL_TOKEN;   // dzp_...

async function panel(method, path, body) {
  const res = await fetch(`${BASE}/api${path}`, {
    method,
    headers: {
      Authorization: `Bearer ${TOKEN}`,
      ...(body ? { 'Content-Type': 'application/json' } : {})
    },
    body: body ? JSON.stringify(body) : undefined,
    signal: AbortSignal.timeout(20_000)   // инвентарь ждёт мод до 10 с
  });

  const data = await res.json().catch(() => null);
  if (!res.ok) throw new Error((data && data.error) || `Панель ответила ${res.status}`);
  return data;
}

// пример: онлайн для страницы сайта
const { players, worldSize } = await panel('GET', '/bridge/players?serverId=srv1');
```

Готовый эталон всех вызовов — `public/js/api.js` в этом репозитории: там
перечислены **все** маршруты панели с их параметрами. Сверяйся с ним, а не с
догадками.

## 8. Чек-лист перед тем, как считать интеграцию готовой

- [ ] Токен только в переменных окружения; в git его нет.
- [ ] Публичная часть работает на `read`-токене и никогда не отдаёт токен в браузер.
- [ ] `serverId` передаётся явно во всех запросах.
- [ ] Один SSE-коннект на процесс, с переподключением и добором через `?since=`.
- [ ] Публичные страницы кэшируются, панель не опрашивается чаще раза в 5 с.
- [ ] `bridge.online === false` показывается как `reason`, а не как «0 игроков».
- [ ] Длина сообщений в игру проверяется по `delivery.maxLength`.
- [ ] Админ-действия закрыты ролями Discord и пишутся в собственный аудит.
- [ ] Панель недоступна → понятная деградация, а не 500 и не молчание.
- [ ] Координаты, инвентари и чат не утекают на публичные страницы.

Если по ходу работы нужен маршрут, которого нет, — сформулируй его как
«нужен `GET /api/…`, возвращающий поля …, чтобы …» и передай владельцу панели.
Не обходи API чтением файлов сервера напрямую.
