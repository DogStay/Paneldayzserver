# DayZ Panel — веб-панель управления серверами DayZ Standalone (Windows)

Локальная панель на Node.js + Express. Создаёт серверы DayZ «с нуля» через мастер,
подписывается на модификации прямо из Steam Workshop, собирает `.bat` запуска,
открывает порты в брандмауэре Windows, следит за обновлениями модов и пишет
подробные отчёты, когда что-то ломается.

Интерфейс — тёмный, анимированный, на русском языке, без единого внешнего ресурса:
шрифты системные, иконки нарисованы прямо в коде. Интернет нужен только в трёх
случаях: разовый `npm install`, работа SteamCMD и поиск модов в Workshop.

## Что умеет

| Возможность | Где живёт |
|---|---|
| **Мастер создания сервера** — 4 шага (название, слоты, пароли → карта, порты, время → папка и SteamCMD → проверка), затем автоматическая установка файлов DayZ Server | `src/services/instances.js` |
| **Несколько серверов** в одной панели: свои папки, порты, моды и настройки у каждого | `src/config.js` |
| **Подписка на модификации** — поиск по названию, Workshop ID/ссылке или **ссылке на коллекцию** (разворачивается целиком), кнопка «Загрузить» с живым прогрессом | `src/services/workshop.js`, `src/services/mods.js` |
| **Локальные моды** — своя папка с модом (например, серверный мод, которого нет в Workshop) подключается вручную или находится автоматически в каталоге сервера | `src/services/mods.js` |
| **Автообновление модов** перед стартом: версия сверяется по `appworkshop_221100.acf`, изменившееся перекладывается в папку сервера | `src/services/mods.js` |
| **Полное удаление мода** — по уровням: из списка, из папки сервера и из репозитория SteamCMD вместе с записью о версии и ключами `.bikey` | `src/services/mods.js`, `steamcmd.js` |
| **Выбор карты через миссии** — список читается из `mpmissions` конкретного сервера: ванильные карты, карты из модов и свои сборки | `src/services/missions.js` |
| **CFTools Cloud** (необязательно) — игроки онлайн, кик, баны, сообщения в игру и RCon, если сервер подключён к CFTools | `src/services/cftools.js` |
| **Автогенерация `.bat`**: `-mod=`, `-serverMod=`, порты, конфиг, профили — всё из настроек панели | `src/services/batgen.js` |
| **Автооткрытие портов** через `netsh advfirewall`, порты берутся из конфига | `src/services/firewall.js` |
| **Старт / стоп / перезапуск**, статус, аптайм, живой лог сервера из `*.RPT`, `*.ADM`, `script.log` | `src/services/serverProcess.js`, `logTail.js` |
| **Правка `serverDZ.cfg`** прямо в браузере + синхронизация имени, паролей, слотов, карты и query-порта | `src/services/serverCfg.js` |
| **Автоперезапуск по расписанию** — каждые N часов или в заданные часы суток, с предупреждениями **прямо в игре** и сохранением игрового времени | `src/services/scheduler.js` |
| **Объявления в чат** — сколько угодно сообщений по кругу или вразнобой, с подстановками `{server}`, `{map}`, `{restart}` | `src/services/announcer.js`, `ingame.js` |
| **Сообщения в игру через BattlEye RCon** — бесплатный канал (`say -1`), пароль и порт берутся из настроек BattlEye сервера; CFTools — как альтернатива | `src/services/battleye.js`, `util/bercon.js` |
| **Интерактивная карта с игроками** — метки в реальном времени, клик по игроку: состояние, инвентарь, его логи, действия (вылечить, накормить, телепорт, выдать вещь, кик) | `public/js/screens/map.js`, `src/services/bridge.js` |
| **Журнал всех действий игроков** — урон, выстрелы, смерти, поднятие вещей, открытие машин, стройка, чат; фильтры по типу, игроку и тексту, живая лента и история по дням | `src/services/eventlog.js`, `public/js/screens/eventlog.js` |
| **Диагностика**: отчёт одной кнопкой + автоматический отчёт при падении сервера | `src/services/diagnostics.js` |

## Требования

* Windows 10/11 или Windows Server 2016+
* [Node.js LTS](https://nodejs.org) (18 или новее), при установке отметьте «Add to PATH»
* [SteamCMD](https://developer.valvesoftware.com/wiki/SteamCMD) — например в `C:\SteamCMD`
* Аккаунт Steam, **на котором куплен DayZ** (анонимно Steam не отдаёт ни файлы сервера, ни моды)
* 15+ ГБ свободного места под каждый сервер

## Установка и первый запуск

### 1. Скачать панель

```bat
git clone https://github.com/DogStay/Paneldayzserver.git C:\DayZPanel
cd C:\DayZPanel
```

### 2. Установить зависимости

Двойной клик по **`install.bat`** (или `npm install --omit=dev`).
Это единственный шаг, требующий интернета помимо самого Steam.

### 3. Разовый вход в Steam (если включён Steam Guard)

```bat
C:\SteamCMD\steamcmd.exe +login ВАШ_ЛОГИН +quit
```

Введите пароль и код Steam Guard. Дальше SteamCMD использует сохранённую сессию,
и пароль в панели можно не указывать вообще.

### 4. Запустить панель

Двойной клик по **`start-panel.bat`** → откроется <http://localhost:8787>.

> **Запускайте от имени администратора** (ПКМ → «Запуск от имени администратора»),
> иначе `netsh` не сможет создавать правила брандмауэра. Панель предупредит об этом
> и всё равно запустится: правила можно применить позже через
> «Порты» → «.bat для админа».

### 5. Создать сервер

При первом запуске панель сама предложит мастер. Дальше:

1. **Основное** — название, слоты, пароль входа, пароль администратора.
2. **Мир и сеть** — карта (Chernarus+ / Livonia / Sakhal), ускорение времени,
   игровой порт и Steam query порт, режим от первого лица.
3. **Установка** — папка сервера, путь к `steamcmd.exe`, логин Steam.
4. **Проверка** — сводка и кнопка «Создать и установить».

SteamCMD скачает файлы сервера (3–5 ГБ), панель создаст `serverDZ.cfg` и `.bat`.
Прогресс виден прямо в мастере, в плашке справа внизу и в консоли логов.

В мастере доступны три карты из самой игры — до установки файлов сервера
`mpmissions` ещё нет и выбирать больше не из чего. После установки карту можно
поменять в любой момент, включая карты из модов и свои сборки миссий, —
см. [«Выбор карты (миссии)»](#выбор-карты-миссии).

### 6. Подписаться на модификации

Вкладка **«Модификации»** → **«Подписаться на модификации»**:

* введите название мода (например `Trader`), его Workshop ID / ссылку **или
  ссылку на коллекцию**;
* нажмите «Найти», добавьте нужные моды кнопкой «Добавить» — а для коллекции
  достаточно одной кнопки **«Добавить все N»**;
* нажмите **«Загрузить»** — SteamCMD скачает моды, панель разложит их в папку
  сервера и скопирует ключи `.bikey` в `keys`.

Порядок модов в списке = порядок в `-mod=`. Зависимости (`@CF`, `@Dabs Framework`)
перетащите наверх мышью.

### 6.1. Коллекции Workshop

Вставьте в поиск ссылку вида
`https://steamcommunity.com/sharedfiles/filedetails/?id=123456789`, указывающую
на коллекцию — панель сама поймёт, что это коллекция, развернёт её состав
(включая вложенные коллекции, до 3 уровней) и покажет все моды списком.
Кнопка «Добавить все» кладёт их в очередь загрузки разом, порядок коллекции
сохраняется.

Если часть модов коллекции скрыта или удалена автором, панель честно напишет,
сколько элементов недоступно, и загрузит остальные.

### 6.2. Локальные модификации

Свой мод, которого нет в Workshop (чаще всего серверный), подключается двумя способами.

**Автоматически.** Положите папку `@MyServerMod` прямо в каталог сервера —
панель найдёт её и покажет в блоке «Папки модов в каталоге сервера» с кнопками
«Как клиентский» / «Как серверный». Один клик — и мод в списке.

**Вручную.** Кнопка **«Локальный мод»** на вкладке «Модификации»: укажите путь
к папке (полный или просто `@MyServerMod` относительно каталога сервера),
название и тип подключения.

Как панель обращается с локальными модами:

* папка **внутри каталога сервера** — панель ничего не копирует и работает с ней
  на месте, ваши файлы не трогаются;
* папка **снаружи** — копируется (или симлинкается, по настройке раскладки)
  в каталог сервера при добавлении и при каждом запуске, поэтому правки в
  исходной папке подхватываются автоматически;
* `.bikey` из `keys` подкладываются в `<сервер>\keys` так же, как у модов Workshop;
* SteamCMD такие моды **не трогает** — обновлять их незачем, и в проверку
  обновлений они не попадают;
* при удалении из панели исходная папка **не удаляется** — стирается только копия,
  сделанная самой панелью.

По умолчанию локальный мод подключается как **серверный** (`-serverMod=`) — это
самый частый случай. Переключить на клиентский можно кнопкой в строке мода.

### 6.3. Автоматический перезапуск

Долгоживущий сервер DayZ со временем «пухнет» по памяти и начинает подтормаживать,
поэтому его принято перезапускать каждые несколько часов. Вкладка
**«Настройки сервера» → «Автоматический перезапуск»**:

* **Каждые N часов после запуска** — самый частый вариант, например каждые 3 часа.
  Отсчёт идёт от момента старта сервера, а после каждого перезапуска начинается заново.
* **В заданные часы суток** — список вида `06:00, 12:00, 18:00, 00:00`, время местное.
* **Предупреждать за** — за сколько минут панель напишет в лог и покажет уведомление
  (например `15, 5, 1`).
* **Предупреждать игроков в игре** — те же предупреждения уходят в чат сервера, чтобы
  игроки успели убрать вещи. Текст настраивается:
  `Плановый перезапуск сервера через {minutes} мин. Уберите вещи в безопасное место.`
  Отдельным полем задаётся сообщение в момент самого перезапуска — оно отправляется
  за пару секунд до остановки сервера, чтобы игроки успели его увидеть.

> Каким каналом сообщения уходят в игру — **BattlEye RCon** (бесплатно) или **CFTools**
> (нужна платная подписка) — выбирается в разделе
> [«Сообщения в игру»](#65-сообщения-в-игру-battleye-rcon-или-cftools). Если ни один канал
> не настроен, предупреждения остаются в панели и логе (как раньше), а на вкладке «Обзор»
> появляется честное предупреждение, что до игроков они не доходят.

Отсчёт идёт только пока сервер работает: если вы остановили его вручную, таймер не тикает.
До ближайшего перезапуска остаётся видимый счётчик — на плитке «Автоперезапуск» во вкладке
«Обзор» и бейджем на карточке сервера.

Плановый перезапуск проходит по тому же пути, что и кнопка «Перезапуск»: панель заново
откроет порты, синхронизирует `serverDZ.cfg`, **проверит обновления модов** и пересоберёт
`.bat`. То есть рестарт заодно подтягивает свежие версии модов.

#### Чтобы игровое время не сбрасывалось

По умолчанию DayZ при каждом старте берёт время из настройки `serverTime` — то есть
после рестарта утро в игре начинается заново. Чтобы время **продолжалось**, нужен
параметр `serverTimePersistent = 1`: сервер сохраняет время суток и продолжает с него.

В панели это переключатель **«Продолжать игровое время после перезапуска»** в том же
разделе. Он включён по умолчанию для новых серверов, а значение записывается
в `serverDZ.cfg` при каждом запуске.

Если включить автоперезапуск и забыть про этот переключатель, панель покажет
предупреждение на вкладке «Обзор» — молча ронять время суток она не станет.

### 6.4. Объявления в чат

Периодические сообщения игрокам — «вы играете на сервере таком-то», правила, ссылка на
Discord, время до перезапуска. Вкладка **«Настройки сервера» → «Объявления в чат»**:

* **Сообщений сколько угодно** — по одному на строку в поле ввода;
* **Интервал** — раз в сколько минут уходит очередное объявление (первое — через интервал
  после запуска сервера, чтобы игроки успели загрузиться);
* **Порядок** — по кругу или в случайном порядке (подряд одно и то же не повторяется);
* **Подстановки**: `{server}` — название сервера, `{map}` — карта, `{restart}` — сколько
  осталось до планового перезапуска («1 ч 20 мин»). Неизвестные подстановки остаются
  в тексте как есть, а не съедаются молча.

Пример списка:

```
Вы играете на сервере {server} — карта {map}.
До планового перезапуска: {restart}.
Discord сервера: discord.gg/…
Правила: не строить на дорогах и в военных зонах.
```

Кнопка **«Предпросмотр»** показывает, что именно увидят игроки, с раскрытыми
подстановками и длиной каждого сообщения (CFTools принимает до 256 символов —
слишком длинное подсвечивается красным и не отправляется). Кнопка
**«Отправить первое сейчас»** отправляет сообщение немедленно, ещё до сохранения
настроек, — удобно проверить текст.

Объявления идут только пока сервер работает и тем же каналом, что и предупреждения о
перезапуске (BattlEye RCon или CFTools — см. следующий раздел). Каждое ушедшее объявление
панель показывает уведомлением и пишет в лог, так что видно ровно то, что увидели игроки.

### 6.5. Сообщения в игру: BattlEye RCon или CFTools

Предупреждения о перезапуске и объявления в чат — это текст, который нужно как-то
передать работающему серверу. Панель умеет двумя способами, выбор в разделе
**«Настройки сервера» → «Сообщения в игру»**:

| Канал | Чего требует | Комментарий |
|---|---|---|
| **BattlEye RCon** | пароль RCon в `battleye\beserver_x64.cfg` | Бесплатно и есть у любого сервера DayZ: RCon поднимает сам BattlEye, ровно этим каналом пишут в чат BEC и DaRT. Панель отправляет команду `say -1 текст` |
| **CFTools** | подключённый CFTools **с платной подпиской** | Отправка сообщений в игру у CFTools платная; если подписки нет, запрос отклоняется, и панель прямо подскажет переключиться на BattlEye |
| **Автоматически** (по умолчанию) | — | BattlEye, если он настроен, иначе CFTools |
| **Не писать в игру** | — | Предупреждения остаются только в панели и логе |

#### Настройка BattlEye RCon

RCon не работает, пока у BattlEye нет пароля, — это самая частая причина «в чат ничего
не приходит». Кнопка **«Настроить BattlEye»** создаёт `battleye\beserver_x64.cfg`
с надёжным случайным паролем:

```
RConPassword <сгенерированный пароль>
RConPort 2306
RestrictRCon 0
```

BattlEye читает этот файл при запуске сервера, поэтому **сервер нужно перезапустить**.
Дальше панель сама берёт из файла пароль и порт — вписывать их в настройки не нужно.
Тот же пароль можно использовать в BEC или DaRT, если вы ими пользуетесь.

Тонкости, которые панель учитывает:

* при запуске сервер создаёт рядом свой `beserver_x64_active_*.cfg` — панель читает
  именно его, если он есть, потому что в нём пароль, который действует **сейчас**
  (правка `beserver_x64.cfg` без перезапуска на работающий RCon не влияет);
* **неверный пароль — опасная ситуация**: BattlEye блокирует IP после нескольких
  неудачных входов. Поэтому при отказе по паролю панель прекращает попытки и просит
  проверить настройки, вместо того чтобы долбиться каждые несколько минут;
* RCon-порт слушается локально, панель обращается к `127.0.0.1` — открывать порт в
  брандмауэре не нужно;
* если русский текст в чате выглядит «кракозябрами», переключите кодировку сообщений
  на **CP1251** (по умолчанию UTF-8);
* сообщение уходит одной строкой, длиннее ~200 символов чат обрезает — «Предпросмотр»
  в объявлениях показывает точный предел выбранного канала.

Кнопка **«Проверить BattlEye RCon»** входит по паролю и запрашивает список игроков —
сразу видно и что связь есть, и сколько людей на сервере (RCon отвечает только когда
сервер запущен). **«Отправить тестовое сообщение»** пишет произвольный текст в чат
тем каналом, который выбран.

### 7. Запустить

Кнопка **«Запустить»** в шапке сервера.

## Что происходит при нажатии «Запустить»

1. **Проверка** путей и портов — при проблеме запуск не начнётся, а панель скажет, чего не хватает.
2. **Брандмауэр** — `netsh advfirewall firewall add rule` для игрового порта, query-порта
   и всех дополнительных диапазонов (in + out, имена вида `DayZ Panel - UDP 2302`).
   Существующие правила не дублируются.
3. **`serverDZ.cfg`** — подставляются `hostname`, `password`, `passwordAdmin`, `maxPlayers`,
   `steamQueryPort`, ускорение времени, карта. Остальное содержимое файла не трогается.
4. **Моды** — SteamCMD проверяет включённые моды по одному; изменившиеся копируются
   (или симлинкаются) в папку сервера, ключи раскладываются в `keys`.
   В лог попадает строка вида `↑ Trader (1590841260): ОБНОВЛЁН`.
5. **`.bat`** — генерируется файл запуска со всеми актуальными параметрами.
6. **Запуск** — `DayZServer_x64.exe` стартует с теми же аргументами, что в `.bat`;
   панель запоминает PID и начинает читать логи профиля.

Любой шаг отключается на вкладке «Настройки сервера» → «Что делать при запуске».

## Панель сама объясняет, почему упал сервер

Движок DayZ сообщает о проблемах на своём языке. Строка вроде

```
SCRIPT (E): @"VPPAdminTools/3_Game/communityframework\rpc\rpcmanager.c,1": Unknown type 'RPCManager'
SCRIPT (E): Can't compile "Game" script module!
```

для админа — загадка, хотя причина почти всегда одна из двух: **не подключён
мод-фреймворк** или он стоит в `-mod=` позже того, кто от него зависит.

Панель читает логи сервера на лету и распознаёт такие случаи:

* `Addon 'X' requires addon 'Y'` — мод X требует Y;
* `Unknown type 'RPCManager'` и подобные — обращение к классу из фреймворка,
  которого нет на сервере;
* `Can't compile "..." script module!` / `Failed to load game scripts!` —
  скрипты не собрались.

Известные фреймворки панель знает по имени: Community Framework (`JM_CF_Scripts`,
`RPCManager`), Dabs Framework, Community Online Tools. Если такого мода нет
в списке, на вкладке «Обзор» появляется красная плашка вида

> **Вероятная причина остановки: не подключён мод «Community Framework»**
> Моды VPPAdminTools, SSM_GOOB_scripts требуют его, поэтому скрипты не
> компилируются и сервер выключается сразу после старта.

с кнопкой **«Добавить „Community Framework“ и поставить первым»** — она скачает
мод через SteamCMD и поднимет его в начало списка, потому что фреймворки должны
грузиться раньше зависимых модов.

Тот же разбор попадает в отчёт о сбое отдельным разделом «ВЕРОЯТНАЯ ПРИЧИНА»
в самом верху файла.

## Если сервер не запускается — диагностика

Панель специально сделана так, чтобы проблему можно было переслать одним файлом.

**Вручную:** вкладка **«Диагностика»** → **«Собрать отчёт»**.
Файл `diagnostic-report-ГГГГ-ММ-ДД_ЧЧ-ММ-СС.txt` появляется **в корне папки панели**
(там же, где `start-panel.bat`). Его можно посмотреть прямо в браузере, скачать
кнопкой или скопировать в буфер.

**Автоматически:** если сервер завершился сам или запуск сорвался, панель сохраняет
`logs\crash-<имя сервера>-<дата>.txt` — без всяких кнопок. На вкладке «Обзор»
появится красная плашка со ссылкой на отчёт.

Что внутри отчёта:

* версия панели, ОС, Node.js, свободная память и место на диске;
* состояние SteamCMD: путь, наличие файлов, логин, есть ли `.acf`;
* по каждому серверу — все пути с пометкой «ЕСТЬ / НЕ НАЙДЕН», настройки, порты;
* список модов: скачан / разложен / включён / версия;
* точная командная строка запуска;
* содержимое папки сервера, `serverDZ.cfg` и сгенерированного `.bat`;
* последние строки лога панели и логов сервера (`*.RPT`, `*.ADM`, `script.log`).

**Пароли (Steam, вход на сервер, админский, RCON) в отчёт не попадают** — они
затираются даже в дампе `serverDZ.cfg`. Файл можно пересылать как есть.

Кроме отчётов панель постоянно пишет `logs\panel-ГГГГ-ММ-ДД.log` (хранятся 14 дней).

## Выбор карты (миссии)

Движок DayZ не знает слова «карта»: он читает из `serverDZ.cfg` строку
`template="dayzOffline.chernarusplus"` и запускает миссию с таким именем из
папки `<сервер>\mpmissions`. Поэтому «выбрать карту» в панели — это выбрать
одну из миссий, которые реально лежат на диске у этого сервера.

**Настройки сервера → Карта (миссия) → «Выбрать карту»**. Панель сканирует
`mpmissions` и показывает всё, что там есть:

* ванильные `dayzOffline.chernarusplus`, `dayzOffline.enoch`, `dayzOffline.sakhal`
  (появляются сразу после установки файлов сервера);
* карты из модов — Namalsk, DeerIsle, Banov и другие, они попадают в `mpmissions`
  вместе с модом-картой;
* свои сборки вида `hardcore.chernarusplus` или `empty.enoch` — та же карта, но
  другой набор лута и настроек. Префикс показывается в названии, чтобы их можно
  было различать.

У каждой миссии панель проверяет наличие `init.c` (без него сервер её не
загрузит) и отмечает, есть ли рядом сохранённый мир (`storage_*`). Выбор
применяется сразу: настройки сервера и `template=` в `serverDZ.cfg` (если правка
конфига не отключена). Работающий сервер продолжает крутить старую карту —
движок читает миссию один раз при запуске, поэтому панель предупредит о
необходимости перезапуска.

Если карта приедет вместе с модом позже, в том же окне есть поле «Своя миссия»:
имя вписывается вручную, а проверка наличия папки пропускается. Забытая или
переименованная миссия не потеряется молча — она останется в списке с пометкой
«нет на диске», попадёт в проблемы сервера на вкладке «Обзор» и в отчёт
диагностики.

> **Смена карты — это новый мир.** Персонажи и постройки лежат в `storage_*`
> внутри папки миссии, у каждой миссии свои. Вернувшись на прежнюю карту, вы
> увидите её мир таким, каким он был.

## Удаление модов: три уровня

Кнопка удаления в списке модов открывает окно, где панель сначала считает, что
именно лежит на диске, и предлагает удалить это по уровням:

| Что удаляется | Когда нужно |
|---|---|
| Запись в списке модов (всегда) | мод больше не нужен этому серверу |
| Папка `@Мод` из каталога сервера | освободить место, убрать мод из `-mod=` окончательно |
| **Файлы из репозитория SteamCMD** — `steamapps\workshop\content\221100\<id>`, остатки закачки в `downloads` и запись о версии в `appworkshop_221100.acf` | мод не нужен вообще; освобождает больше всего места |
| Ключи `.bikey` из `<сервер>\keys` | чтобы не оставлять подписи удалённых модов |

Про запись в `appworkshop_221100.acf` легко забыть, и тогда получается странное:
файлов нет, а SteamCMD считает мод установленным и на запрос обновления отвечает
«уже актуально», ничего не скачивая. Панель убирает запись сама (рядом остаётся
`appworkshop_221100.acf.backup`), поэтому мод потом скачивается заново честно и
целиком.

Две страховки:

* **Репозиторий SteamCMD один на всю панель.** Если тот же мод подключён к
  другому серверу, удаление файлов сначала запрещается — с объяснением, каким
  серверам он нужен. Продолжить можно галочкой «Удалять принудительно»; тем
  серверам мод придётся скачать заново.
* **Пока SteamCMD работает, файлы не удаляются** — иначе незавершённая закачка
  вернёт их обратно.

Ключи `.bikey` определяются по папке `keys` самого мода, поэтому чужие ключи в
общей папке не пострадают. Если файлов мода уже нет, определить его ключи
невозможно — панель честно об этом скажет.

Папку локального мода, лежащую вне каталога сервера, панель не удаляет никогда:
это ваш исходник, а не копия, сделанная панелью.

Скачанные моды, не подключённые ни к одному серверу, панель показывает отдельным
списком «бесхозных» — там у каждого есть кнопка удаления с диска.

## CFTools Cloud (необязательно)

Панель управляет сервером «снизу»: файлы, процесс, моды, порты. Список игроков,
кик, баны и сообщения в игру она узнать не может — DayZ этого процессу не
отдаёт. Если сервер подключён к [CFTools Cloud](https://cftools.com), панель
умеет спрашивать всё это у него.

Интеграция **выключена по умолчанию**, и пока она выключена, панель к CFTools
не обращается вообще — вкладки «CFTools» просто нет.

CFTools может быть и каналом для [предупреждений о перезапуске](#63-автоматический-перезапуск)
и [объявлений в чат](#64-объявления-в-чат), но **отправка сообщений в игру у CFTools
доступна только на платной подписке**. Без неё выбирайте BattlEye RCon — он бесплатный
и умеет то же самое, см. [«Сообщения в игру»](#65-сообщения-в-игру-battleye-rcon-или-cftools).
Оба канала спрятаны за модулем `services/ingame.js`, так что остальной панели всё равно,
чем именно доставляется текст.

### Как включить

1. На [developer.cftools.cloud](https://developer.cftools.cloud) создайте
   приложение → получите **Application ID** и **Secret**.
2. Там же выдайте приложению **гранты** на нужный сервер и (если нужны баны) на
   банлист. Без гранта API отвечает `no-grant`.
3. **Настройки сервера → CFTools Cloud**: включите переключатель, впишите
   Application ID и Secret, сохраните настройки.
4. Нажмите **«Мои ресурсы в CFTools»** — панель покажет серверы и банлисты,
   доступные приложению, и подставит **Server API ID** (свой у каждого сервера
   панели) и **Banlist ID** одним кликом. Сохраните ещё раз.
5. **«Проверить связь»** — панель логинится, читает гранты и запрашивает
   информацию о сервере.

### Что появляется на вкладке «CFTools»

* **Сервер**: связь с CFTools, аптайм, игровое время, следующий перезапуск по
  расписанию CFTools, состояние игровой интеграции (мода CFTools/GameLabs).
* **Игроки онлайн** — имя, пинг, страна, Steam64, число прошлых банов, метка
  подозрительного IP. Обновляются каждые 30 секунд, пока вкладка открыта.
* **Действия по игроку**: личное сообщение в игру, кик с причиной, бан.
* **Сообщение всем игрокам** и **RCon-команда** (например `#shutdown` —
  спрашивает подтверждение, потому что останавливает сервер сразу).
* **Баны**: список с поиском по CFTools ID, IP или комментарию, снятие бана,
  добавление бана на час / день / 7 / 30 дней или навсегда. Банить можно по
  Steam64 — панель сама найдёт CFTools ID.

Ограничения, о которых стоит знать:

* Список игроков, кик и сообщения работают только когда на сервере установлена
  и запущена игровая интеграция CFTools (мод CFTools / GameLabs). Панель
  предупредит, если она не отвечает.
* У Data API строгие лимиты частоты запросов: панель отправляет их по одному с
  паузой и понятно сообщает о `429`, но кнопку «Обновить список» лучше не
  нажимать без остановки.
* Токен доступа живёт около суток и обновляется автоматически.
* Secret хранится в `config/config.json` в открытом виде и не отдаётся обратно
  в браузер — как и пароль Steam.

## Карта, игроки и журнал действий (мод-мост)

Панель управляет сервером снаружи: файлы, процесс, моды, порты. Что происходит
**внутри** игры — кто где стоит, кто в кого стрелял, кто открыл чужую машину —
сервер сам наружу не отдаёт. Для этого нужен серверный мод-мост
`@DayZPanelBridge`, и вкладки **«Карта»** и **«Логи»** работают через него.

Мод **серверный**: подключается через `-serverMod=`, игрокам скачивать нечего,
ключи и подписи не нужны, никто из них о нём даже не узнает.

**Мод входит в комплект панели и уже собран:**

* готовый аддон — `mod/@DayZPanelBridge` (скопировать рядом с `DayZServer_x64.exe`);
* исходники — `mod/DayZPanelBridge` (Enforce Script, комментарии на русском);
* пересборка — `mod/build-pbo.bat` (через DayZ Tools или встроенный упаковщик);
* установка и разбор проблем — [`mod/README.md`](mod/README.md).

### Как устроена связь

Обмен идёт файлами в папке профиля — ни портов, ни интернета, и обе стороны
спокойно переживают перезапуск друг друга:

```
<профиль сервера>\panel\
  hello.json      мод пишет при старте: версия, мир, размер карты
  snapshot.json   мод перезаписывает каждые ~3 секунды: игроки, координаты, состояние
  out\ev_*.json   события: панель читает, складывает в журнал и удаляет
  in\cmd_*.json   команды панели: мод выполняет, отвечает и удаляет
```

Полное описание протокола и **готовое задание для написания мода** лежит в
[`docs/bridge-mod-prompt.md`](docs/bridge-mod-prompt.md): там перечислены все
типы событий, все команды и требования к производительности. Панель уже
реализует свою половину этого протокола (`src/services/bridge.js`), поэтому мод
достаточно собрать по заданию — договариваться ни о чём не нужно.

Пока мода нет, вкладка «Карта» показывает инструкцию и кнопку «Подготовить папку
обмена» (создаёт `panel\in` и `panel\out` заранее), а вкладка «Логи» — уже
записанную историю, если она есть.

### Вкладка «Карта»

* метки игроков в реальном времени, с направлением взгляда; жёлтая — без
  сознания, красная — кровотечение;
* сетка координат по километрам, колесо мыши — масштаб, перетаскивание — сдвиг;
* спутниковую подложку можно добавить самому: положите квадратную картинку в
  `public/maps/<мир>.jpg` (например `chernarusplus.jpg`) — панель подхватит её.
  Готовых снимков в панели нет: это чужие текстуры на гигабайты;
* клик по метке или строке в списке открывает карточку игрока: здоровье, кровь,
  голод, жажда, выносливость, температура, что в руках, в каком транспорте;
* действия по игроку: сообщение на экран, вылечить, накормить и напоить, задать
  или изменить любой показатель, выдать предмет, телепортировать, посмотреть
  **инвентарь** (запрашивается у сервера по кнопке) и **его личные логи**, кик.

### Вкладка «Логи»

Журнал всего, что делают игроки: вход и выход, урон с оружием, зоной и
дистанцией, выстрелы, смерти и убийства, поднятие и выброс вещей, открытие
машин, контейнеров и палаток, стройка и разбор баз, чат, посадка в транспорт и
любое законченное действие в игре.

* фильтры по типу события (галочками, сгруппированы по смыслу), по игроку
  (Steam64) и по тексту — ник, класс предмета, оружие;
* живая лента: новые события появляются сверху и коротко подсвечиваются;
* кнопка «Показать более старые» для истории, глубина — от суток до 30 дней;
* сводка за сутки: сколько каких событий записано.

Хранение: свежие события лежат в памяти панели (мгновенные ответы), вся история
— построчным JSON в `logs/events/<serverId>/<ГГГГ-ММ-ДД>.jsonl`. Формат
построчный специально: дописывать дёшево, читать можно с конца, и файл не
портится, если панель убить на полуслове. Файлы старше 30 дней панель удаляет.

## Поиск модов: как это работает

1. **По Workshop ID или ссылке** — запрос `ISteamRemoteStorage/GetPublishedFileDetails`.
   Ключ Web API не нужен, работает всегда. Это самый надёжный путь.
   Ссылка на коллекцию выглядит так же, как ссылка на мод, поэтому панель сначала
   спрашивает `ISteamRemoteStorage/GetCollectionDetails` — если пришёл состав,
   значит это коллекция, и она разворачивается целиком.
2. **По названию с ключом Web API** — `IPublishedFileService/QueryFiles`.
   Ключ бесплатно берётся на <https://steamcommunity.com/dev/apikey> и вводится
   в «Настройки сервера» → «SteamCMD и аккаунт Steam».
3. **По названию без ключа** — разбор страницы поиска Workshop. Работает «как есть»:
   если Valve поменяет вёрстку, поиск по названию может перестать находить —
   поиск по ID продолжит работать всегда.

## Большие моды (5–10 ГБ и больше)

SteamCMD регулярно обрывает закачку тяжёлых модов Workshop с ошибкой
`Timeout downloading item` — это его известная особенность, а не поломка панели.
Панель рассчитана на это:

* коллекция скачивается **за один вход в Steam** (см. следующий раздел), а мод,
  который в общей сессии не дался, панель докачивает **отдельно** — обрыв на
  тяжёлом моде не отменяет загрузку остальных;
* при обрыве панель **повторяет попытку** — SteamCMD складывает недокачанное в
  `steamapps\workshop\downloads` и продолжает с того же места, ничего не теряя;
* в лог пишется, сколько уже лежит на диске:
  `Huge Map Pack (123): попытка 2 из 5. На диске уже 3.4 ГБ — SteamCMD продолжит с этого места`;
* пока идёт закачка, панель раз в 15 секунд показывает объём — видно, что процесс жив,
  даже когда SteamCMD молчит;
* безнадёжные ошибки (нет подписки, неверный пароль, мод удалён автором, кончилось
  место) **не повторяются** — панель сразу говорит, в чём дело;
* перед закачкой панель сверяет свободное место: SteamCMD держит мод дважды —
  сначала в `downloads`, потом в `content`, поэтому моду на 8 ГБ нужно около 18 ГБ.

### Когда мод скачался, но «не установился»

Самая частая беда с тяжёлыми модами выглядит так: в логе видно
`скачано 8.4 ГБ из 8.4 ГБ`, SteamCMD завершается с ненулевым кодом (обычно 10),
а папки мода в `steamapps\workshop\content` нет. Мод целиком лежит в
`steamapps\workshop\downloads` — SteamCMD скачал его, но не смог выполнить
финальный перенос.

Панель доводит установку до конца сама:

1. проверяет, что закачка действительно полная — по счётчику
   `BytesDownloaded`/`BytesToDownload` в файле состояния SteamCMD, а если его
   нет, то по размеру мода из Workshop;
2. переносит папку из `downloads` в `content`;
3. отмечает мод установленным в `appworkshop_221100.acf`, скопировав туда
   реальные `manifest` и `timeupdated` из секции `WorkshopItemDetails`
   (оригинал файла сохраняется рядом как `.acf.backup`).

Третий шаг важен: без него SteamCMD считал бы мод неустановленным и при каждой
проверке обновлений скачивал бы все гигабайты заново. Если проставить отметку
не удалось (в файле состояния нет данных о версии), панель помечает мод бейджем
**«установлен переносом»**, исключает его из автопроверки обновлений и даёт в
строке мода кнопку **«Обновить принудительно»** — чтобы обновить его тогда,
когда вы сами этого захотите.

Недокачанный мод панель не трогает: если закачка неполная, она честно скажет,
сколько процентов есть, и предложит запустить загрузку ещё раз — остаток
докачается с места обрыва.

Настройки повторов — в `config/config.json`, секция `steam`:

```jsonc
"downloadRetries": 5,           // сколько раз пробовать докачать один мод
"downloadTimeoutMinutes": 180,  // сколько ждать одну попытку
"batchSize": 25                 // сколько модов уходит в SteamCMD за один вход
```

Если мод настолько большой, что не укладывается и в пять попыток, просто нажмите
«Загрузить» ещё раз: прогресс сохраняется, и следующая попытка продолжит с места обрыва.

## «Rate Limit Exceeded»: почему коллекция скачивалась не целиком

Steam ограничивает не гигабайты, а **число входов в аккаунт**. Если качать моды
по одному, коллекция из 20 модов — это 20 входов подряд, и примерно с шестого
Steam начинает отвечать `ERROR (Rate Limit Exceeded)`: SteamCMD выходит с кодом 5,
ничего не скачав. Именно так «терялась» большая часть коллекции.

Что делает панель:

* **один вход на всю пачку.** Все моды передаются в одну сессию SteamCMD
  (`+workshop_download_item` подряд), поэтому 21 мод — это один вход, а не 21.
  Размер пачки задаётся `steam.batchSize`;
* **докачивает поштучно только то, что не получилось.** В логе это видно как
  `Пакетная загрузка: готово 18 из 21. Оставшиеся 3 мод(ов) панель докачает по одному`;
* **выдерживает паузу между входами** (несколько секунд), чтобы не упираться в лимит;
* **пережидает лимит, а не сдаётся.** Получив `Rate Limit Exceeded`, панель ждёт
  1 → 3 → 5 → 10 минут и продолжает сама. В логе:
  `Steam ограничил частоту входов. Жду 3 мин и продолжу автоматически — закрывать панель не нужно`;
* если Steam не пускает даже после долгих пауз, панель честно говорит, что нужен
  перерыв на 30–60 минут; уже скачанное при этом не пропадает.

## Мод скачан, но сервер его «не видит»

Папка мода в каталоге сервера может существовать и при этом быть пустой —
например, копирование оборвалось, потому что запущенный сервер держал файлы.
Снаружи всё выглядит нормально: мод «скачан», папка на месте, — а движок не
находит ни одного `.pbo` и ругается на зависимости.

Панель считает мод разложенным не по факту существования папки, а по числу
аддонов в ней:

* в списке модов такой мод получает красный бейдж **«разложен не полностью»**
  с указанием, сколько аддонов есть и сколько должно быть;
* раскладка проверяет результат копирования и падает с понятной ошибкой
  («скопировано 2 аддонов из 47»), а не отчитывается об успехе;
* **«Проверить обновления»** и запуск сервера перекладывают такие моды сами,
  даже если Steam говорит, что версия актуальна;
* удаление папки повторяется несколько раз, если Windows ещё держит файлы
  (`EPERM`/`EBUSY`) — сразу после остановки сервера это обычное дело.

Копирование идёт асинхронно, поэтому панель и её лог остаются живыми, пока
на диск переливается мод на несколько гигабайт.

## «Addon 'X' requires addon 'Y'»: чего не хватает

На этой ошибке DayZ показывает **модальное окно и останавливает запуск**, пока
кто-нибудь не нажмёт OK. Со стороны это выглядит как «сервер запущен, но его
нет в списке», поэтому панель разбирает такие строки **сразу**, не дожидаясь
падения, и показывает вывод на вкладке «Обзор».

Движок ругается именами аддонов (`FOG_Data_Patches`), а админ видит папки
(`@Forward Operator Gear`). Панель связывает одно с другим по именам `.pbo`
в папках включённых модов и выдаёт один из трёх ответов:

* **зависимость есть, но грузится позже** — «Forward Operator Gear стоит ниже,
  чем The First Line | GEAR»; рядом кнопка **«Исправить порядок модов»**,
  которая двигает мод-зависимость выше зависимого;
* **зависимости нет, но есть «родственные» аддоны** (`FOG_*.pbo` лежат в
  `@Forward Operator Gear`, а нужного файла среди них нет) — значит, установлена
  **другая версия** мода, чем та, под которую собран зависимый мод: обновите или
  переустановите его кнопкой «Обновить принудительно»;
* **нет ничего похожего** — мод-зависимость просто не подключён; что именно
  нужно, написано на странице зависимого мода в Workshop (Required Items).

## Раскладка модов при запущенном сервере

Работающий `DayZServer_x64.exe` держит `.pbo` модов открытыми, и Windows не даёт
ни удалить, ни перезаписать папку мода — раскладка падает с
`EPERM, Permission denied: ...\@Dabs Framework`.

Панель не пытается это обойти и не трогает сервер молча:

* если сервер запущен, при нажатии «Загрузить», «Проверить обновления»,
  «Разложить» или «Обновить принудительно» появляется вопрос
  **«Остановить и разложить»**;
* при согласии моды сначала **скачиваются при работающем сервере**, и лишь на
  время раскладки панель останавливает сервер, а сразу после — запускает его
  снова (без повторного захода в SteamCMD);
* при отказе загрузка всё равно выполняется, а раскладка сообщает понятным
  текстом, что сервер держит файлы, — вместо непонятного `EPERM`.

---

## Режимы раскладки модов

* **copy** (по умолчанию) — мод физически копируется из
  `steamapps\workshop\content\221100\<id>` в `<сервер>\@Имя`. Надёжно, занимает место дважды.
* **symlink** — junction на папку workshop: экономит диск, обновление применяется
  мгновенно. Требует, чтобы оба пути были на одном томе NTFS, и обычно прав администратора.

В обоих режимах `.bikey` копируются в `<сервер>\keys` физически — иначе сервер их не подхватит.

## Как определяется, что мод обновился

DayZ Workshop не даёт версию без обращения в Steam, поэтому панель делает так:

1. Читает `steamapps\workshop\appworkshop_221100.acf` и запоминает `manifest` +
   `timeupdated` каждого мода.
2. Запускает `steamcmd +workshop_download_item 221100 <id>` для всех включённых
   модов одним вызовом — SteamCMD сам скачает только изменившееся.
3. Перечитывает `.acf`. Изменился `manifest`/`timeupdated` — мод считается обновлённым:
   он заново раскладывается в папку сервера, а в лог попадает строка `↑ <Имя>: ОБНОВЛЁН`.

Дополнительно панель показывает бейдж «есть обновление», если в секции
`WorkshopItemDetails` время публикации новее установленного.

## Доступ к панели снаружи: вход по мастер-ключам

По умолчанию панель слушает `127.0.0.1` и доступна только с самой машины —
вход не спрашивается, как и раньше. Как только `panel.host` смотрит в сеть
(`0.0.0.0`), **вход по мастер-ключам включается сам**: панель управляет файлами,
процессами и SteamCMD, и открытый доступ к ней равен доступу к машине.

Как это выглядит:

1. Поставьте `panel.host` = `0.0.0.0` в `config/config.json` и перезапустите панель.
2. В окне панели появятся ключи:

   ```
   [auth] МАСТЕР-КЛЮЧИ ДЛЯ ВХОДА В ПАНЕЛЬ (действуют до перезапуска):
   [auth]    1.  UHQK-7EZK-MP3N
   [auth]    2.  YW9M-V8ST-YH5Y
   [auth]    3.  HYJX-D5V3-ZG55
   ```

3. С любого компьютера откройте `http://ваш-адрес:8787` — панель покажет
   страницу входа, куда вводится любой из ключей.

Правила, по которым это работает:

* **ключи новые при каждом запуске панели** и живут только в памяти — на диск не
  пишутся, в отчёты диагностики не попадают. Перезапустили панель — прежние
  ключи мертвы;
* ключей по умолчанию три (`panel.auth.keyCount`, 1…10) — раздать разным людям;
* ключ обменивается на сессию в cookie, сессия держится
  `panel.auth.sessionHours` часов (по умолчанию 12);
* **подбор блокируется**: пять неудачных попыток с адреса — и он отдыхает
  10 минут; все попытки видны в логе панели;
* всё, кроме страницы входа, закрыто — и API, и поток событий;
* в **Настройках сервера → «Доступ к панели»** видны ключи (можно скопировать и
  передать), активные сессии с адресами и временем входа, кнопки «выпустить
  новые ключи» и «закрыть все сессии». Выпуск новых ключей не выкидывает тех,
  кто уже вошёл.

Настройки:

```jsonc
"panel": {
  "host": "0.0.0.0",
  "auth": {
    "enabled": "auto",   // auto — вход нужен, когда host не 127.0.0.1; true/false — принудительно
    "keyCount": 3,
    "sessionHours": 12,
    "trustProxy": false  // true, если панель за reverse-proxy (адрес брать из X-Forwarded-For)
  },
  "tls": {
    "enabled": false,
    "certFile": "C:\\certs\\panel.crt",
    "keyFile": "C:\\certs\\panel.key"
  }
}
```

### HTTPS — обязательно, если открываете в интернет

По `http://` мастер-ключ и всё содержимое панели идут по сети **открытым
текстом**. Два способа закрыть это:

* **Reverse-proxy с сертификатом** (рекомендуется): Caddy или nginx перед
  панелью, панель слушает `127.0.0.1`, `panel.auth.enabled` = `true`,
  `panel.auth.trustProxy` = `true`. Caddy получает сертификат Let's Encrypt сам.
* **Свой сертификат прямо в панели**: заполните `panel.tls` — панель поднимется
  по `https://`, и cookie сессии станет `Secure`.

Панель предупреждает в логе, если слушает сеть без HTTPS, и то же предупреждение
показывает на странице входа.

## Безопасность

Панель слушает `127.0.0.1` по умолчанию; для доступа снаружи есть вход по
мастер-ключам (раздел выше). В интернет её стоит выставлять только через HTTPS.

Пароль Steam, если указан, хранится в `config/config.json` в открытом виде и
никогда не отдаётся обратно в браузер и не попадает в отчёты. Надёжнее выполнить
`steamcmd +login ЛОГИН +quit` один раз вручную и оставить поле пустым.

**Пароль RCon BattlEye** панель по умолчанию не хранит вовсе — читает его из
`beserver_x64.cfg` при каждой отправке. Если вы всё же вписали пароль в настройки панели,
он лежит в `config/config.json` и в браузер не отдаётся. RCon слушается локально;
выставлять RCon-порт в интернет не нужно и не следует.

То же относится к **Secret приложения CFTools**: он лежит в `config/config.json`
рядом и наружу не отдаётся. Ключи выдаются приложению, а не аккаунту, поэтому
если они утекли — перевыпустите Secret на developer.cftools.cloud, и старый
перестанет работать. Гранты стоит выдавать только на те серверы и банлисты,
которыми панель действительно управляет.

## Решение проблем

**«Порт 8787 занят»** — измените `panel.port` в `config/config.json`.

**Правила брандмауэра не создаются** — панель запущена без прав администратора.
Перезапустите `start-panel.bat` от имени администратора либо нажмите
«Порты» → «.bat для админа» и выполните `generated\open-firewall.bat` с правами администратора.

**SteamCMD: `Rate Limit Exceeded`** — Steam ограничил частоту входов. Панель
пережидает это сама (1 → 3 → 5 → 10 минут) и продолжает загрузку; закрывать её
не нужно. Если сообщение повторяется даже после долгих пауз — сделайте перерыв
на 30–60 минут, уже скачанное не пропадёт.

**SteamCMD: `Login Failure`** — выполните вход вручную
(`steamcmd +login ЛОГИН +quit`), подтвердите Steam Guard и повторите.

**`EPERM, Permission denied: ...\@МодНейм`** — сервер запущен и держит файлы
модов. Согласитесь на «Остановить и разложить» либо остановите сервер вручную.

**SteamCMD: `No subscription`** — аккаунт не владеет DayZ.

**Поиск по названию ничего не находит** — вставьте Workshop ID или ссылку на мод,
либо укажите ключ Steam Web API в настройках.

**Сервер стартует и сразу падает** — откройте автоматический отчёт из папки `logs`.
Чаще всего это `verifySignatures = 2` без нужных `.bikey` в `<сервер>\keys` или
мод-зависимость, стоящий в `-mod=` ниже зависящего от него (поднимите `@CF` вверх).

**Лог сервера пуст** — сервер запущен без `-dologs -adminlog -netlog` либо указана
не та папка профиля. Проверьте «Настройки сервера» → «Пути сервера».

**Мод не появился в игре** — убедитесь, что у него бейдж «готов», он включён
чекбоксом и попал в предпросмотр на вкладке «Файл запуска».

**Большой мод не скачивается, `Timeout downloading item`** — это норма для SteamCMD.
Панель повторит попытку сама; если попыток не хватило, нажмите «Загрузить» ещё раз
или увеличьте `steam.downloadRetries`. Прогресс между попытками не теряется.

**`скачано 8.4 ГБ из 8.4 ГБ`, а мод не появился** — SteamCMD не смог перенести
готовую закачку из `downloads` в `content`. Панель делает это сама, см. раздел
«Когда мод скачался, но „не установился“». Если в логе написано, что перенос не
выполнен из-за неполной закачки — просто запустите загрузку ещё раз.

**Мода не хватает места** — SteamCMD хранит тяжёлый мод дважды (в `downloads`
и в `content`), то есть моду на 8 ГБ нужно около 18 ГБ свободного места на том же
диске. Панель предупреждает об этом в логе до начала загрузки.

**После перезапуска в игре снова утро** — выключено «Продолжать игровое время».
Включите переключатель в разделе «Автоматический перезапуск» и перезапустите сервер:
в `serverDZ.cfg` должно быть `serverTimePersistent = 1`.

**`install.bat` открывается чёрным окном и ничего не пишет** — так вело себя
раннее издание панели: в .bat стояла строка `chcp 65001`, а сам файл был в UTF-8.
cmd.exe запоминает позицию в файле в байтах, после смены кодовой страницы
пересчитывает её заново, теряет место и молча прекращает выполнение. Сейчас все
.bat-файлы панели записаны в **CP866** — родной кодировке консоли Windows — и
никакого `chcp` в них нет. Если правите их вручную, сохраняйте в той же кодировке
(в Блокноте это «Кодировка: ANSI» на русской Windows) и не добавляйте `chcp`.

Если чёрное окно всё же появилось, откройте «Пуск → cmd», перейдите в папку панели
(`cd /d "путь к папке"`) и запустите `install.bat` оттуда: окно не закроется,
и текст ошибки останется на экране.

**Сервер стартует и выключается за минуту, в логе `Unknown type` или
`Can't compile`** — не хватает мода-фреймворка. Смотрите плашку на вкладке
«Обзор»: панель называет нужный мод и добавляет его одной кнопкой.

**Установка или запуск «ничего не делают»** — панель теперь всегда доводит итог задачи
до экрана: ошибка появляется всплывающим сообщением, а в мастере — текстом с кнопкой
«Повторить установку» (повтор продолжает уже созданный сервер, а не плодит новые).
Если сообщение всё же не появилось, откройте консоль внизу окна и вкладку «Диагностика» —
там будет полный вывод SteamCMD.

**Локальный мод помечен «папка не найдена»** — исходную папку переместили или
переименовали. Удалите мод из списка и подключите заново по новому пути.

**Коллекция найдена, но модов в ней меньше, чем на странице Steam** — часть
элементов скрыта или удалена автором; панель показывает, сколько именно
недоступно. Такие моды можно добавить только по прямому ID, если он известен.

## Разработка

```bash
npm install
npm start           # http://localhost:8787
npm run check       # быстрая проверка синтаксиса
```

Единственная внешняя зависимость — Express. Фронтенд собирать не нужно.

Панель запускается и на Linux/macOS (удобно для доработки интерфейса): `netsh` и
запуск `DayZServer_x64.exe` там не работают, о чём панель честно предупреждает,
остальные функции доступны.

Для отладки поиска модов без интернета можно подменить адреса Steam:

```bash
DAYZPANEL_STEAM_API=http://127.0.0.1:9999 \
DAYZPANEL_STEAM_COMMUNITY=http://127.0.0.1:9999 npm start
```
